# Contributing to the Attack and Defense Playbook for Microsoft Entra

Thank you for helping keep this community-driven playbook accurate, practical, and useful to identity and security practitioners. The playbook documents common Microsoft Entra ID attack scenarios and their detection and mitigation considerations. The contribution overview in the [README](./README.md#how-to-become-part-of-the-project-and-contribute) describes the kinds of input the project welcomes.

## Ways to contribute

- Propose a new attack or defense scenario, or report outdated content, by opening an issue.
- Improve an existing chapter with a focused pull request.
- Share detection logic, defensive guidance, references, diagrams, or implementation experience that is relevant to a chapter.
- Review proposed content for technical accuracy, clarity, and safe defensive use.

## Before submitting a pull request

- Search existing issues and pull requests to avoid duplicate work.
- Keep the change focused and explain the scenario, assumptions, affected products or services, and source material where applicable.
- Follow the chapter structure used throughout the playbook: attack description, detection, mitigation, and relevant MITRE ATT&CK mappings.
- Use clear Markdown and verify links, queries, diagrams, and file paths before submitting.
- Clearly label sample commands, queries, and configurations. Do not include credentials, tokens, tenant identifiers, personal data, customer data, or other sensitive information.
- Ensure that you may share all submitted text, code, queries, images, and data. Include required attribution and licensing information for third-party material.

## Responsible disclosure and safe research

Do not use public issues or pull requests to disclose vulnerabilities, active incidents, or sensitive tenant information. Do not submit instructions, payloads, or artifacts intended to enable unauthorized access or harm. Keep contributions focused on authorized testing, detection, mitigation, and defensive education.

If you have a private concern about conduct or sensitive content, contact a repository maintainer through GitHub rather than posting the details publicly.
